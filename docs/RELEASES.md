# Releases

Owned by: Build Engineer (cuts releases), Lead (decides when). This file
defines versioning and the release checklist; history lives in
`CHANGELOG.md` (generated by `tools/release/release.mjs`).

## Versioning

- `0.x.y` — pre-release. `x` maps to SPEC milestones: `0.1` prototype,
  `0.2` vertical slice, `0.3` alpha, `0.4` beta. `y` for fixes within a
  milestone.
- `1.0.0` — release. Patch/minor bumps from there per semver.

## Release checklist

1. Milestone exit criteria in `docs/SPEC.md` met (milestone status →
   `reached`).
2. No `open` or `in-progress` blocker/major bugs in `docs/BUGS.md`.
3. Assets rebuilt: `assets/build/` current with `docs/ASSETS.md`.
4. Build/export using the current engine pack's conventions
   (`engines/<engine>/conventions.md`).
5. Changelog: `node tools/release/release.mjs --version <x.y.z>` (previews,
   then re-run with `--yes`).
6. `git tag v<x.y.z>` and push.

## Hotfixes

Patch a released version directly: fix, verify in `docs/BUGS.md`, bump `y`,
run the checklist from step 4.
